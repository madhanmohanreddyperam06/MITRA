# MITRA PostgreSQL Deployment Guide for Render

## Overview

This guide explains how to deploy MITRA with PostgreSQL database on Render.com.

## Prerequisites

- Render account (free tier available)
- GitHub account with MITRA repository
- PostgreSQL knowledge (basic)

## Architecture

- **Backend:** FastAPI application deployed on Render Web Service
- **Database:** PostgreSQL database deployed on Render PostgreSQL
- **Frontend:** Streamlit application (to be deployed separately)

---

## Step 1: Prepare Repository

### 1.1 Verify Configuration Files

Ensure your repository has:
- `render.yaml` - Render configuration file
- `requirements.txt` - Python dependencies
- `backend/.env.example` - Environment variable template

### 1.2 Environment Variables Required

The following environment variables are required:

```
DATABASE_URL - Automatically set by Render from PostgreSQL service
JWT_SECRET_KEY - Auto-generated by Render
APP_ENV - Set to "production"
DEBUG - Set to "false"
CORS_ALLOWED_ORIGINS - Your frontend domain
```

---

## Step 2: Deploy PostgreSQL Database on Render

### 2.1 Create PostgreSQL Service

1. Log in to [Render](https://render.com)
2. Click **"New +"** → **"PostgreSQL"**
3. Configure:
   - **Name:** `mitra-db` (or your preferred name)
   - **Database:** `mitra_db`
   - **User:** `mitra_user`
   - **Region:** Choose closest to your users
   - **Plan:** Free (or paid for production)
4. Click **"Create Database"**
5. Wait for PostgreSQL to be provisioned

### 2.2 Get Connection Details

1. Go to your PostgreSQL service
2. Click **"Connect"** tab
3. Note the **Internal Database URL** (used by backend in same project)
4. The format will be: `postgresql://mitra_user:password@host:port/mitra_db`

---

## Step 3: Deploy Backend on Render

### 3.1 Create Web Service

1. Click **"New +"** → **"Web Service"**
2. Connect to your GitHub repository
3. Configure:
   - **Name:** `mitra-backend`
   - **Branch:** `main`
   - **Root Directory:** Leave empty (repository root)
   - **Runtime:** Python 3
   - **Build Command:** `cd backend && pip install -r ../requirements.txt`
   - **Start Command:** `cd backend && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
4. Click **"Advanced"**
5. **Environment Variables:**
   - `DATABASE_URL`: Connect to PostgreSQL service (click "Connect to Database")
   - `JWT_SECRET_KEY`: Click "Generate" (or add your own)
   - `APP_ENV`: `production`
   - `DEBUG`: `false`
   - `CORS_ALLOWED_ORIGINS`: `https://your-frontend-domain.onrender.com`
6. Click **"Create Web Service"**
7. Wait for deployment to complete

### 3.2 Verify Deployment

1. Click on your web service
2. Check the **"Logs"** tab for errors
3. Visit the URL (e.g., `https://mitra-backend.onrender.com`)
4. Should return health status

---

## Step 4: Run Database Migrations

### 4.1 Access Render Shell

1. Go to your backend web service
2. Click **"Shell"** (near the top right)
3. Wait for shell to initialize

### 4.2 Run Migrations

In the Render shell, run:

```bash
cd backend && alembic upgrade head
```

Expected output:
```
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume non-transactional DDL.
INFO  [alembic.runtime.migration] Running upgrade  -> 001_initial_schema
INFO  [alembic.runtime.migration] Running upgrade 001_initial_schema -> 002_add_users_table
INFO  [alembic.runtime.migration] Running upgrade 002_add_users_table -> 003_add_single_admin_constraint
INFO  [alembic.runtime.migration] Running upgrade 003_add_single_admin_constraint -> 8bc28335b2c5
```

### 5.1 Run Admin Creation Script

In the same Render shell, run:


## Step 6: Verify Setup

### 6.1 Test Health Endpoint

```bash
curl https://mitra-backend.onrender.com/
```

Should return health status.

### 6.2 Test Authentication

```bash
curl -X POST https://mitra-backend.onrender.com/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username_or_email": "admin", "password": "adminmitra@123"}'
```

Should return a JWT token.

## Step 7: Deploy Frontend (Optional)

### 7.1 Create Frontend Web Service

1. Click **"New +"** → **"Web Service"**
2. Connect to same GitHub repository
3. Configure:
   - **Name:** `mitra-frontend`
   - **Branch:** `main`
   - **Root Directory:** `frontend`
   - **Runtime:** Python 3
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `streamlit run main.py --server.port=$PORT --server.address=0.0.0.0`
4. **Environment Variables:**
   - `API_BASE_URL`: `https://mitra-backend.onrender.com`
5. Click **"Create Web Service"**

### 7.2 Update CORS

Update backend `CORS_ALLOWED_ORIGINS` to include frontend URL:
```
https://mitra-frontend.onrender.com
```

## PostgreSQL-Specific Changes

### 1. Database Driver
- Changed from `pymysql` to `psycopg2-binary`
- Connection string format: `postgresql://user:password@host:port/database`

### 2. Triggers
- MySQL triggers converted to PostgreSQL functions
- PostgreSQL uses plpgsql for trigger functions
- Single admin constraint maintained via PostgreSQL triggers

### 3. Connection Pooling
- PostgreSQL-specific connection pooling
- Pool size: 10, max overflow: 20
- Health checking enabled (pool_pre_ping)

## Troubleshooting

### Migration Errors

If migrations fail:
1. Check PostgreSQL service is online
2. Verify DATABASE_URL is set correctly
3. Check backend logs for connection errors
4. Ensure psycopg2-binary is installed

### Connection Errors

If backend can't connect to database:
1. Verify both services are in same Render account
2. Check DATABASE_URL environment variable
3. Ensure PostgreSQL service is not in "Suspended" state
4. Check Render service logs

### Admin Creation Errors

If admin creation fails:
1. Verify migrations completed successfully
2. Check users table exists
3. Verify no admin already exists
4. Check backend logs for errors

## Security Best Practices

1. **Change Admin Password:** Change the default admin password immediately
2. **Use Strong JWT Secret:** Render auto-generates, but verify it's secure
3. **Enable SSL:** Render provides SSL by default
4. **Monitor Logs:** Regularly check Render logs for suspicious activity
5. **Update Dependencies:** Keep dependencies updated for security patches

## Render Free Tier Limitations

- **PostgreSQL:** 90 days free, then requires paid plan or data deletion
- **Web Service:** Spins down after 15 minutes of inactivity (cold starts)
- **Database:** 1GB storage limit on free tier
- **Bandwidth:** 100GB/month limit on free tier

For production, consider upgrading to paid plans.
